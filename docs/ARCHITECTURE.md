# Architecture

## Overview

Scarce has two halves that talk through `postMessage`:

- **Extension host** (`src/`, Node, bundled with esbuild): registers the
  command, owns persistence, opens editors.
- **Webview UI** (`scarce-ui/`, React + Vite, pnpm workspace package): renders
  the sidebar. It holds no persistent state; the extension is the source of
  truth.

Shared types live in `models/` and are imported by both halves, so the message
protocol is type-checked on both sides.

## Data model

```ts
interface Cairn {
  id: string; // UUID, generated by the store
  rootPath: string; // absolute root the path is relative to
  filePath: string; // relative to rootPath, forward slashes
  codeSnippet: string; // exact text captured
  lineRange: [number, number]; // 0-indexed, inclusive; the UI shows +1
  comment: string; // required, trimmed
  severity: 'normal' | 'high' | 'critical';
  resolved: boolean; // Alpha addition; absent in older files = false
}
```

Rules:

- Line numbers are **0-indexed in data**, 1-indexed only at the display layer.
- `filePath` always uses `/`, regardless of OS.
- Nothing is ever removed automatically. Only an explicit user delete removes
  a cairn.

## Storage

**Decision:** one JSON file, `cairns.json`, in `context.globalStorageUri`.

Why not `workspaceState`: cairns must be visible across workspaces so the
sidebar can show "all of the user's cairns" when no repo is open (feature #13).
Why not a file in the repo: personal cairns must not touch the repository;
that is what global cairns (v0.3) are for.

Format:

```json
{ "version": 1, "cairns": [{ "id": "...", "...": "..." }] }
```

- Writes go to `cairns.json.tmp` and are renamed over the target, so a crash
  cannot leave a partial file.
- All mutations run through a single in-process queue so overlapping saves
  cannot lose records.
- A missing file is an empty store. An unparseable file raises
  `CorruptCairnFileError`; the file is **left untouched** and the error is
  surfaced to the user. It is never silently overwritten.
- `resolved` is optional on read (defaults to `false`), so the file `version`
  stays `1` during alpha. Any breaking shape change bumps `version`.

### Store contract (alpha)

```ts
interface CairnStore {
  list(): Promise<Cairn[]>;
  add(input: CairnInput): Promise<Cairn>;
  update(
    id: string,
    patch: { comment?: string; severity?: CairnSeverity; resolved?: boolean },
  ): Promise<Cairn>;
  delete(id: string): Promise<void>;
}
```

`update` and `delete` on an unknown id throw `CairnNotFoundError`.
Only `comment`, `severity` and `resolved` are patchable in alpha; `id`,
location and snippet are immutable.

## Message protocol

All messages are discriminated unions on `type`, defined in
`models/messages.ts`.

**Webview to extension**

| `type`            | Payload       | Effect                                         |
| ----------------- | ------------- | ---------------------------------------------- |
| `ready`           | none          | Extension flushes pending draft and sends list |
| `saveCairn`       | `input`       | Create a cairn                                 |
| `updateCairn`     | `id`, `patch` | Edit comment/severity, or toggle `resolved`    |
| `deleteCairn`     | `id`          | Confirm in a native dialog, then delete        |
| `editCairn`       | `id`          | Ask extension to show the edit form            |
| `navigateToCairn` | `id`          | Open the file and select the lines             |
| `changeRoot`      | none          | Pick a different root (add form only)          |
| `cancel`          | none          | Close the form                                 |

**Extension to webview**

| `type`             | Payload                         | Effect                                                   |
| ------------------ | ------------------------------- | -------------------------------------------------------- |
| `cairnsChanged`    | `cairns: Cairn[]`               | Replace the list; sent on ready and after every mutation |
| `showForm`         | `mode: 'add' \| 'edit'`, values | Replace the list with the form                           |
| `saveResult`       | `ok`, optional `error`          | Result of add or update                                  |
| `changeRootResult` | `ok`, root/path or `error`      | Result of root change                                    |

This table is the **contract the implementation must follow**; if the
implementation needs to deviate, update this file in the same pull request.

Principles:

- The extension is the single source of truth. After any mutation it re-sends
  the full list (`cairnsChanged`); the UI never mutates its own copy.
- The webview never touches the filesystem or the editor. It asks; the
  extension acts.
- Destructive confirmation uses a native VS Code modal
  (`window.showWarningMessage` with `{ modal: true }`) so it works regardless of
  webview state.

## Navigation

`navigateToCairn` resolves `join(rootPath, filePath)`, opens the document, and
selects `lineRange` (start of first line to end of last line), then reveals it
in the centre of the editor. If the file no longer exists, the user sees an
error message and the cairn is left untouched (drift handling arrives in v0.1).

## Security

- The webview runs with a strict CSP: no inline scripts, per-load nonce,
  `localResourceRoots` limited to `scarce-ui/dist`.
- Message payloads from the webview are untrusted: the extension validates the
  shape and looks cairns up by `id` instead of trusting paths sent from the UI.
- No network access and no telemetry.

## Testing strategy

- **Unit (Vitest, `scarce-ui`)**: components, hooks, client.
- **Extension host (`@vscode/test-cli`, Mocha)**: store (with an in-memory
  `CairnFs`), message handler, sidebar provider, path logic.
- **Manual ([MANUAL_TESTING.md](MANUAL_TESTING.md))**: what only a human sees:
  theme, layout in a narrow sidebar, flow, real files.
